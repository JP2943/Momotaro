## 2. P5.5 で何が変わったか（一段落で）

P5 は Area を **1 枚だけ** Single で読み、移動のたびに暗転していた。
P5.5 は Area を **Additive で最大 2 枚**持ち、**暗転せずに横（縦）へスライド**して隣へ移る。
出発した Area は撤去せず**非活動のまま預け**、すぐ戻れば同じ Scene をそのまま使う。
カメラは**常駐が 1 つだけ**で、Area ごとには持たない。

### 変わった契約（P6 で踏みやすいもの）

| P5 | P5.5 |
|---|---|
| 読込済み Area は常に 1 | **Active 1 ＋ 非活動 1 の合計 2**（枠は保持を入れても増えない） |
| 「どの Area に居るか」は Scene 内を探して言える | **`CurrentAreaProvider` で言う**（2 つの Area の部品が同時に載っている） |
| Area 初期化は一生に一度 | **構築は Scene ごとに一度・入場準備は入場のたび**（§6.2 手順 5） |
| 失敗したら読み直した Scene へ戻る | **残っている Scene へ戻す**（旧 Scene 保持 Rollback） |
| 移動は暗転（Fade） | **スライド**。Fade は死亡再開・Interact 扉・退避に残る。**両方 `AreaTransitionService` が所有する** |
| Camera は Area 側 | **常駐 1 つ**（付録 A） |

**P5 の要求は 1 件も差し替えていない**（付録 C.36）。P5 の Scene と Single 方式の中では
「常に 1 枚」は今も真である。P5.5 は別配置（`Phase55` / `Phase55NS`）を足す形で入った。

オーナーの報告は「**真っ暗**」だったが、外側の画素だけを切り出して測ると

## 4. P6 の最初の一手（推奨）

**保存の対象を決める前に、「保存してはいけないもの」を先に固定する。**
P5.5 が増やしたものは、ほとんどが**実行時の事情**である。

`P55_後続課題.md` §3 に分けて書いた。要点だけ再掲する。

- **保存してよい**：訪問済み・調査・門 Flag・Encounter クリア（周期つき）・徳・再出現周期・
  Actor の値（Snapshot）・いま居る **AreaId** と入口の **StableId**。
- **保存してはいけない**：Scene handle・実体ハンドル・在留台帳・カメラの演出位置・
  スライドの進行度・表示代理・待機表示の通算・前面判定・**主人公のワールド座標**。

座標を保存しないのが効く。入口の StableId から置き直す形（`PlaceArrivals`）にしておけば、
**地形を作り直した日に壁の中へ復帰する**ことがない。

### 採取元を取り違えない（工程 P55-15f で書き直した）

| 何を | どこから |
|---|---|
| **現在地**（AreaId・入口の StableId）・**Actor 値** | **活動中の Area から 1 つだけ** |
| **門・調査・Encounter のクリアなどの論理進行** | **非活動 Area のぶんも含めて全部**（`GameSessionState` が Area ごとに持っている） |

**後者を活動中だけに絞ると、留守のあいだに開けた門が復帰後に閉じる。**
「二重になる」のは Scene を 2 つぶん書く場合であって、論理進行を両方書くことではない。

### 保存が絡むと危ない 4 経路（必ず試す）

1. **保持した Area が載っているとき**に保存する（実 Scene は 2 枚。採取元は上の表）。
2. **スライドの最中**に保存する（§6 は「Commit だけが確定」。保存も Commit の後）。
3. **`ReleaseFailed` を抱えたまま**保存する（解放できていない Scene は実行時の事情）。
4. **復帰直後にロードが走らないこと。**
   **距離による先読みは工程 P55-15c で撤去した**（付録 C.42）。
   いまは**遷移が受理されたときにしか読まない**ので、
   復帰直後に載っているのは**復帰先の 1 枚だけ**である。
   台帳が空から始まることと、**隣はまだ載っていない**ことを前提に書く。

## 5. 触るときに知っておくと早いこと

### 5.1 常駐 3 点は Rig が自分で足す

Camera・表示代理・待機表示は `AreaCameraRigHost` が自分の物体へ足す。
前面判定（`AppFocusHost`）も同じ。**Prefab 側の配線に頼らない**——
配線漏れが追いにくい壊れ方になるため。

### 5.2 Scene 操作の所有は 1 か所で言う

通常 Fade・死亡再開・Interact 扉・Launcher 退避は、すべて
`AreaSlideTransitionRunner.DiscardStagedForSingleLoad()` を通す。

| 名前 | 意味 | ロードを止めるか |
|---|---|---|
| `HasLiveSceneOperation` | **終端していない操作** | **止める** |
| `HoldsRemainingScene` | 操作は終端したが実 Scene を預かったまま | 止めない（Single が置き換える） |
| `HasPendingRetire` | 撤去に**失敗して**抱えたまま | Slide の受理を断る |
| `SingleLoadClaimed` | Single の**発行権** | 撤去の再試行を断らせる |

**「失敗した」と「まだ掴んでいる」は別**（付録 C.20／C.34）。
ここを混ぜると、一度解放に失敗しただけで死亡再開も扉移動も通らなくなる。

### 5.3 落ち着いた状態は「1 枚」か「2 枚」——**枚数で検査を書かない**

**工程 P55-15c で意味が変わった**（付録 C.42）。距離による先読みは撤去され、
**読むのは遷移が受理されたときだけ**になった。

| いつ | 実 Scene |
|---|---|
| 起動直後・初訪問の Area を歩いている | **1 枚**（隣はまだ載っていない。近づいても読まない） |
| 隣へ渡ったあと | **2 枚**（出発側を撤去せず引き継ぐ。裁定 2・付録 C.29） |
| そのまま歩き回る | **2 枚のまま**（距離で手放さない） |

**枚数で検査を書かないこと**——P5.5 の中で**4 回**意味が変わった（付録 C.36.3 ＋ C.42）。
見たいものに合わせて、`IAreaSceneHost.IsLoaded` か Scene handle の一致で言う。

### 5.4 待機表示の契約（工程 P55-15f で確定）

- **「読み込み中」は、受理から 0.3 秒以上待たされたときだけ出す。**
  短い待ちで一瞬だけ字が出ると**ちらつきとして見える**ので、**出さない側が要件**である。
- **ロード開始より前に描画することは求めない**（前回裁定にあったが、実装されていなかった。
  機能を足さず**仕様の側を実装へ合わせて確定**させた。記録 060）。
- ただし**計時はロード要求より前に始める**。あとで数え始めると
  **0.3 秒がロード待ちを含まない**ので、操作できない時間が実際より短く見積もられる（付録 C.31）。

### 5.5 俯角に依存する定数がある（工程 P55-15e）

`CameraFacingBillboard._depthOffset`（既定 **1.5**）は**俯角 55 度・主人公の絵の高さで実測した値**である。
**カメラの俯角を変えるなら、この値を measure し直すこと**（必要量は H·tan θ）。
`AgainstTheWalls_TheHeroIsStillDrawn` が**窓の両側**（奥 0.9 以上／手前 0.55 未満）で縛っているので、
俯角を変えて足りなくなれば落ちる。

**戦闘 VFX（`PlayerSlashVfxPresenter` ほか）の 0.5 は測っていないので変えていない。**

### 5.6 作業の約束（セッションをまたいで有効）

- ブリッジへ送るコマンドは **1 呼び出しにつき 1 つ**。`&&` で繋がない。
- `br.sh` の第 2 引数は**外側の波括弧を含めない**。含めると壊れた JSON になり、**黙って拾われない**。
- テストを書き換えたら `run-tests` の前に `compile-status`（force）。
- **PlayMode は 4 分割**で回す（P5.5 だけでも上限 600 秒を超える）。分け方は**クラス名**で書く。

  | 分割 | filter |
  |---|---|
  | 1 | `P55SlideTransitionPlayTests`（64 件・約 155 秒） |
  | 2 | `P55RoundTripPlayTests`（13 件・約 147 秒） |
  | 3 | `P55(ActivityGate\|AreaBundle\|AreaScope\|CameraSlide\|ConnectionInput\|DisplayProxy\|NorthSouthSlide\|Preload\|ReentryPreparation\|RenderCapture\|ResidentCamera\|Uniqueness)PlayTests`（72 件・約 240 秒） |
  | 4 | 非 P55 の **26 クラス**を名前で並べる（115 件・約 187 秒） |

- **テストを持たないクラス名を filter に混ぜない。**
  `PlayModeInputFocusFixture` は `[SetUpFixture]` で**テストが 0 件**。
  混ぜると**完了通知が来ず**、ブリッジが 600 秒で強制的に再生モードを抜ける——
  「Editor が壊れた」に見える。**否定先読みの filter（`^(?!...P55).*`）は全件に一致する。**
- **必須の照合は非 Passed を悲観的に採る。** 落ちた実行記録は混ぜず、撮り直す。
- **追跡ファイルの一括 revert は禁止。** 切り分けはソースを一時的に戻して作り直す
  （単一ファイルなら `git show HEAD:path > path`）。
- git-lfs は `$HOME/bin/git-lfs` を per-command flag で。書き込む git コマンドの直前に
  `.git/index.lock`（あれば `HEAD.lock`）を `_to_delete/git_locks/` へ `mv` する。
- `Debug.Log` はブリッジ経由では読めない。**値は assert のメッセージへ埋める**
  （読みたいだけなら一時的に `Assert.Fail` を置いて読み、必ず外す）。
- 新しい `.cs` の `.meta` の guid は**資産パスの md5**。
- **Scene の生成物に触る変更をしたら、`build-phase55-world` と `build-exploration-trial` の両方を回す。**
- 検証器・生成器を回すと P5／試遊の Scene に **fileID の振り直しだけ**の差分が出る。
  **既知の雑音**なので、中身が変わっていないことを確かめて commit から外す
  （`git diff --numstat` で追加＝削除なら振り直しだけ）。

## 6. 工程を通して繰り返し効いた考え方

P5.5 で 60 の記録を書いたが、効いたのは同じ数個だった。

### 作ったものについて

- **API があることと、繋がっていることは別。** 仕掛けを作った工程で「渡す側」を後回しにすると、
  以後の工程は全部通るのに**絵は一度も動いていない**（Move のコマは実際そうだった）。
- **Unity の通知は「有効な間だけ」届く。** 部品を止める仕組み（活動ゲート）を入れたら、
  その部品が**通知で維持している状態**は全部たな卸しする（報告①の原因）。
- **「一度しか走らない」は仕様の裏返しでしかない。** 入場ごとに作り直していたから一度で正しかった。
  仕様が変わると、**正しかった実装がそのまま欠陥になる**。
- **ある設定を前提に決めた値は、その設定を変えたときに全部洗い出す。**
  定数の根拠に「どの条件で決めたか」が書いてあるなら、**その条件を変える工程がその定数を洗う**
  （報告④の原因。doc に「45 度俯瞰では」と書いてあったのに読み返さなかった）。

### 検査について

- **規則そのものは、規則だけが動く場所で見る。** 実 Scene には他の仕組みも動いていて、
  壊した規則を埋め合わせる——「実 Scene で見ているから強い」は成り立たない。
- **最初から通った検査は、注入で落ちることを確かめる。** 落ちて初めて、
  「0 だった」が「見ていなかった」ではないと言える。
- **「出さない」「増えない」側が抜けやすい。** しかも**増えようのない数**で書くと空振りする——
  どの操作がその数を動かすのかを先に確かめる。
- **遅延の度合いに寄りかかる検査は書かない。** 「遅らせる」ではなく「終わらせない」。
- **直しの代償も測り、受入は窓の両側で書く。** 片側だけ見ると、
  片方を直して片方を壊したことに気付けない（報告④の `_depthOffset`）。
- **前提を名乗る検査は、その前提が成り立っていることを数で言う。**
  「壁際」を名乗って壁に届いていない検査は、**「問題なし」に見える**——
  いちばん読みにくい空振りである。
- **画面全体の平均は、部分の真っ黒を隠す。** 見たい領域が画面の一部なら、**その領域だけを切り出す**。

### 報告と文書について

- **報告された症状と、測った事実は違うことがある。直す前に測る**（報告③）。
- **検査の名前が正直でも、報告が正直とは限らない。**
  検査が何を見ているかと、それが契約の何を満たすかは、**別に確かめる**（記録 060）。
- **満たせていない要件は、黙って満たしたことにしない。**
  機能を足すか、**要件の側を実際に合わせて確定させる**かのどちらかで、
  後者なら**なぜ外してよいのか**を書く。
- **仕組みを撤去した工程は、その仕組みを前提に書いてある文書を全部たどる。**
  とくに**次工程が読む引き継ぎ文書**は、古い記述が**誤実装を誘発する**。
- **自動で埋められない一片は、検査で名指しして残す。** 注記だけにすると
  「全部見てある」と読まれる。境目そのものを assert すれば消えない。
