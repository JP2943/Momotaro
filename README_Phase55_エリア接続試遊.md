# Phase 5.5 エリア接続試遊 — 触りかた

隣り合う 2 つのエリアを、**暗転せずにカメラを滑らせて**行き来するための試遊環境。
P5 と違って、遷移の最中は**両方のエリアが同時に描かれています**。

**仮素材のままなので、見た目ではなく振る舞いを見るためのもの。**
仕様の正本は `Momotaro_P55_Sliding_Transition_Spec_v1.0.md`。
受入の記録は `P55_統合受入結果.md`。

---

## 1. 2 つの配置がある

**同じ生成器から、設定だけを変えて 2 つ作ってあります。** 接続の軸が違います。

| 配置 | 並び | 進む向き | 起動 Scene |
|---|---|---|---|
| **東西** | A の**東**に B | 右へスライド | `Scenes/Tests/Phase55/SCN_Phase55_ConnectionTrial.unity` |
| **南北** | S の**北**に N | 上へスライド | `Scenes/Tests/Phase55NS/SCN_Phase55NS_ConnectionTrial.unity` |

どちらかの起動 Scene を開いて Play してください。エリア A（南北なら S）の開始点から始まります。

| Scene | 用途 |
|---|---|
| `SCN_Phase55_AreaA.unity` / `SCN_Phase55NS_AreaS.unity` | 手前側のエリアを直接開く |
| `SCN_Phase55_AreaB.unity` / `SCN_Phase55NS_AreaN.unity` | 奥側のエリアを直接開く |

**進行は配置ごとに別物です。** 東西と南北で AreaId を分けてあるので、
片方で開けた門や調べた記録はもう片方に持ち越されません（付録 B.5 の裁定）。
同じセッションで 2 つの配置を混ぜないでください。

再生成は Unity のメニューから。手で直さず**作り直す**のが正しい直し方です。

- `Momotaro / Phase 5.5 / Generate Connected World` … **両方の配置**を作り直す
- `Momotaro / Phase 5.5 / Validate Connected World` … **両方の配置**を検査する

> 未保存の変更がある Scene が開いていると、生成は**何もせずに断ります**。

## 2. 操作

| したいこと | キー |
|---|---|
| 移動 | `W` `A` `S` `D` |
| 調べる・レバー・扉 | `E`（押して離す） |
| 攻撃 | `J` |
| 死亡後の再開 | `Enter` |

**隣のエリアへ行くには、出入口の範囲内で出口の方向へ 0.15 秒押し続けます。**
触れただけ・立っているだけでは移動しません。押し出しで一瞬めり込んだときに
飛ばされないための約束です。

**到着したら一度キーを離してください。** 押しっぱなしのまま到着しても、
入力が一度切れるまで次の遷移は始まりません（そのまま往復し続けないため）。

## 3. 見てほしいところ

### 3.1 スライドそのもの

- **画面が暗転しない。** 遷移の最中もずっと地形が見えています。
- **カメラは接続の向きへ動く。** 東西なら主に横、南北なら主に縦。
  **通路の端から入ったときは、そのぶん斜めに流れます**（工程 P55-14d で仕様変更）。
  通路の幅（4m）の内側に収まる範囲で、行き先の入口へ向かって寄ります——
  実測では接続方向 3.15m に対して横 1.5m（東西・通路の端から）。
  **これが目障りに感じたら教えてください。** 「入った横位置のまま向こうへ出る」形
  （到着位置を横にずらす案）も検討候補として残っています。
- **スライドの距離が短くなりました**（工程 P55-14d）。
  以前はカメラが境界の手前 4m に止まってから約 9m 動いていましたが、
  いまはエリア内で主人公に付いてくるので、動くのは「出口から入口まで」の
  3.15m（東西）／2.5m（南北）だけです。**速すぎる・物足りない**と感じたら教えてください。
- **画面の向きと世界の向きが一致する。** 北へ進めば行き先が画面の上から来ます。
- **主人公は 1 人だけ映る。** 遷移中に見えているのは表示代理で、
  実体は両側とも隠れています。
- **歩いて見える。** スライド中の主人公は Move の 6 コマで足を動かします
  （止まった 1 枚が滑っていく形ではありません）。
- **一度渡ったエリアは、以後ずっと見えたままになります**（工程 P55-15c で仕様変更。
  **初回だけは、渡るまで隣が見えません**——次の 3.1.2 に詳しく書きました）。
  境界の向こうに虚空（黒い抜け）は出ません。

### 3.1.1 エリアの中では画面が切り替わりません（工程 P55-14d）

**以前は、同じエリアの中でも場所によって画面が切り替わっていました。**
部屋ごとにカメラの基準位置が決まっていて、跨ぐたびに 0.15 秒の寄せ直しが走っていたためです。
門（開通する扉）と仕切りの抜け口が、ちょうどその境目のすぐ内側にあったので、
**門を通ると必ず画面が動く**ように見えていました。

いまは**エリアの中では普通の移動と同じようにカメラが付いてきます**。
画面が滑るのは**エリアをまたぐときだけ**です。

- エリア内を歩いて、**画面が切り替わる場所が 1 つも無い**ことを見てください。
- 門を開けて通っても、**そこでは画面が動きません**。
- エリアの端まで寄ると、**エリアの外側が画面に入ります**——そこは背景が覆っています。
  **黒い抜けが見えたら不具合です**ので、どの場所かを教えてください。
- **読み込みが遅いときだけ、右下に 1 行出ます。** 0.3 秒以上待たされたときだけで、
  画面を暗くしません。ふつうに歩いている間は出ません。
- **別のウィンドウへ切り替えると、スライドが止まります。** 戻ると続きから動きます
  （戻った瞬間に飛んで到着していることはありません）。

### 3.1.2 隣のエリアがいつ見えるか（工程 P55-15c。試遊報告②③への回答）

**試遊で 2 つ報告をいただきました。**

> エリア内を歩き回っていると、時折ゲームが一瞬止まり、ロードが行われたような挙動が見られた。

> 隣接エリアの状況は近づくと表示されるようになっているのでしょうか？
> 試遊時は、隣接エリアが移動するまで真っ暗なときと、
> 移動する前から地形が見えているときの両方がありました。

**どちらも同じ仕組みが原因でした。** 以前は「出入口から 6m 以内に入ったら隣を読み始める」
という作りだったので、

- その 6m の線をまたぐたびに**読み込みが走り、一瞬止まる**（報告②。実測 45.7 ms）
- 読み終わるのが間に合えば**渡る前から地形が見える**、間に合わなければ**真っ暗**
  ——つまり**同じ場所でも毎回違って見える**（報告③の「両方あった」）

**いまの仕様はこうです**（ご提案どおりの形になりました）。

| いつ | 隣のエリア | 読み込み |
|---|---|---|
| **まだ一度も渡っていない** | **見えません。**外側は背景の一枚板が覆います | **読みません**（歩いても止まりません） |
| **渡ることが決まった瞬間** | 読み込み中。遅ければ右下に 1 行出ます | **ここで 1 回だけ読みます** |
| **一度渡ったあと** | **ずっと見えたままです。**距離では消えません | **読み直しません**（往復しても 0 回） |

- **エリア内を歩いているあいだ、読み込みは一度も起きません。**
  まだ一瞬止まるようなら、それは**ロード以外の原因**なので教えてください
  （どのあたりで、どれくらいの頻度かも分かれば助かります）。
- **待ち時間は「渡る」と決めた瞬間だけにまとまります。**
  そこで待つのはプレイヤーにも理由が分かる場所だからです。
- **「近づくと見える」は取り下げました。** 初回に渡るまで隣を読まないので、
  近づいただけで隣の実地形が見えることはありません。
- **未訪問の側は、背景の一枚板が覆っています。** これは「黒い抜け」ではありません。
  ただ、**遠景として読めないほど暗く見える・不具合に見える**ようなら教えてください——
  そこは仮の表現で、作り込みは後工程に残しています。

### 3.2 境界の手前

**まず門を開けてください。** レバー（`E`）を引かないと境界へ行けません。

- 東西：東の通路を塞ぐ板
- 南北：部屋を端から端まで塞ぐ板

### 3.3 奥のエリア

到着したら、遭遇 Trigger に入ると戦闘が始まります。倒すと徳が入ります（初回 10 ＋ 12 ＝ 22）。
**一度倒した相手は、同じ周期のあいだ再訪しても湧きません。**

## 4. いまの状態で見えてしまうもの（既知・設計の判断待ち）

| 見えるもの | なぜ | どうなるか |
|---|---|---|
| 目印のラベルが重なって読みにくい | 両エリアの目印が同時に映るため | 仮素材の置き換えで解消予定 |
| 地形の外側が、床より少し暗い一枚板になっている | **背景の補完**。まだ読み込まれていない側と、エリアの外側を覆うための仮の面です | 正式な遠景素材に差し替え予定（面の置き方はそのまま）。**初回に渡るまで隣を読まなくなったので、この面が見えている時間は以前より長くなりました**（工程 P55-15c） |
| 犬丸が出撃していないとき、スライド中は映りません | 退場中は表示代理を作らない設計です（§7.2） | 到着後に所定の位置へ出ます |

**虚空（黒い抜け）は出ないようになりました。** 以前の README にあった
「境界の向こうが虚空になる」「到着直後に来た方向へ虚空の帯が残る」は、
**旧エリアの保持**と**背景の補完**で塞いであります
（以前ここに書いていた「距離による先読み」は工程 P55-15c で撤去しました。3.1.2）。
もし黒い抜けが見えたら**それは不具合**なので、どの場面かを教えてください。

**死亡して再開すると、倒した敵がもう一度湧きます**（再出現の周期が進むため。§9.1）。
倒し直すと徳がまた入ります。ここを「稼げてよいか」はコアループの検討待ちです。

## 5. 触っていて変だと思ったら

`P55_統合受入結果.md` の記録に、工程ごとの「何を見て何を直したか」が入っています。
既知の残りは記録の末尾の「申し送り」にまとまっています。

自動の検査は次の 2 つで回ります（Editor 常駐ブリッジまたはメニューから）。

- `Validate Connected World` … 2 つの Scene の**関係**（境界・通路・並び・カメラ軸・覆い・接続 Data）
- PlayMode テスト … 実キーでの往復・スライド・戦闘・死亡再開・実描画

実描画の記録は `Recordings/P55-06b/<配置>/` に 16:9 の連番で残ります
（`00_before` → `04_arrived`）。

**見た目受入をするときは `試遊確認票_Phase55.md` を開いてください。**
見なくていいもの（機械側で見てあるもの）と、人間しか判断できない 4 つが分けてあります。

残っているものは `P55_後続課題.md` にまとまっています。
次の段（P6 保存設計）へ渡すものは `引き継ぎ書_P55完了_P6移行.md` を見てください。
